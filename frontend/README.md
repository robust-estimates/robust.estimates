# Frontend кредитного кабинета

React-интерфейс подключён к REST API gateway. Регистрация, вход, компании, заявки, решения и документы используют backend. Заявки в localStorage не хранятся. В sessionStorage находятся JWT и незавершённые поля формы; сами выбранные файлы после перезагрузки страницы нужно выбрать повторно, если они ещё не были загружены на сервер.

## Запуск всего проекта

Из корня репозитория:

```sh
make up
```

Открыть `http://localhost:3000`. Swagger доступен по `http://localhost:3000/docs/` и `http://localhost:8080/docs/`.

Демонстрационные логины: `client@demo.local`, `employee@demo.local`. Пароль берётся из корневого `.env` (`DEMO_PASSWORD`); для стандартного `.env.example` — `Demo-Credit-2026!`. Можно зарегистрировать собственного клиента. Сотрудник входит отдельной учётной записью; смена кабинета не даёт клиенту банковские права. SMS, Госуслуги, восстановление пароля и настоящая электронная подпись пока отсутствуют.

## Разработка

Нужен Node.js 24 и npm. Backend должен работать через Compose.

```sh
cd frontend
npm ci
npm run dev
```

Открыть `http://127.0.0.1:5173`. Vite проксирует `/api`, `/docs` и `/openapi.yaml` в gateway на порту 8080. В Docker Nginx делает то же самое на порту 3000. По умолчанию frontend использует относительный `/api/v1`, поэтому CORS не требуется. Для отдельно размещённого API можно задать `VITE_API_BASE_URL` при сборке/разработке и настроить разрешённый origin gateway.

## Подключённые сценарии

- Вход и регистрация через backend, отображение ошибок и выход при истечении JWT.
- Каталог, актуальные условия и обязательные документы из API.
- Создание/обновление компании через «Мои данные» в меню профиля. Для первого персонального подбора интерфейс запрашивает профиль компании.
- Персональный подбор через `/recommendations`; расчёт через `/calculations`.
- Создание черновика, проверка комплектности, загрузка PDF/PNG/JPEG до 10 МиБ и отправка заявки.
- Список заявок, история, обновление статусов каждые четыре секунды на открытой вкладке.
- Скачивание документов с авторизацией.
- Альтернативное предложение банка, принятие по offerId, отказ и демонстрационная выдача.
- Банковская очередь, реальный скоринг с факторами, ручное решение и запрос дополнительных документов.

Деньги преобразуются из рублей в целые копейки на границе API, ставки — из процентов в базисные пункты. `business` интерфейса соответствует `unsecured` backend. Остальные идентификаторы совпадают. Изменения заявки отправляются с актуальным `If-Match`, команды — с `Idempotency-Key`. Компания и продукт берутся из серверных данных, фиктивный вход и локальная генерация номеров заявок удалены.

Выдача кредита остаётся симуляцией backend. Оценочные платежи кредитной линии и овердрафта не являются фактическим графиком. Редактирование отправленной заявки доступно после запроса дополнительных данных, а решение сотрудника — только в статусе MANUAL_CHECK.

## Проверки

```sh
npm run build
npx playwright install chromium
npm run test:e2e
```

Для проверки Docker-интерфейса:

```sh
FRONTEND_URL=http://localhost:3000 npm run test:e2e
```

Если пароль сотрудника отличается от `.env.example`, передайте `DEMO_PASSWORD` в окружении тестов. Браузерные тесты создают синтетические аккаунты, компании, документы и заявки в текущей БД. Backend должен быть запущен.

Актуальные интеграционные тесты находятся в `tests/integration/` и выбраны в Playwright config. Исполняемый каталог теперь задаётся backend.

## Основные файлы

| Файл | Назначение |
|---|---|
| `src/api.ts` | HTTP-клиент, JWT, преобразование контрактов, файлы и расчёт |
| `src/App.tsx` | Маршруты, загрузка данных, отправка заявок и решений, обновление статусов |
| `src/Login.tsx` | Вход и регистрация |
| `src/CompanyProfile.tsx` | Профиль компании и финансовые сведения |
| `src/Applications.tsx` | Форма, список, история и карточка заявки |
| `src/DocumentUploads.tsx` | Выбор и проверка файлов |
| `src/Specialist.tsx` | Очередь сотрудника, скоринг и ручные решения |
| `src/Catalog.tsx` | Каталог и результаты персонального подбора |
| `src/products.ts`, `src/creditData.ts` | Оформление карточек и типы; параметры подменяются данными API до показа кабинета |
| `vite.config.ts` | Локальное проксирование API |
| `Dockerfile`, `nginx.conf` | Production-сборка и проксирование в Compose |
