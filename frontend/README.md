# Альфа-бизнес — кредитный кабинет

Фронтенд на React, TypeScript и Vite по вручную доработанным макетам **справа** в Figma. Использованы оригинальные логотип, иконки и изображения, локальный Roboto и CSS без UI-фреймворка. Основной размер макета — 1672 × 1016; для меньших экранов предусмотрена адаптивная вёрстка.

## Запуск

Требуется Node.js 22.12+ или 24+.

```powershell
cd frontend
npm.cmd ci
npm.cmd run dev
```

Адрес: http://127.0.0.1:5173. В PowerShell используется `npm.cmd`, чтобы не зависеть от политики запуска `npm.ps1`. В других оболочках можно использовать `npm`.

## Экраны и сценарии

| Экран                          | Адрес                       |
| ------------------------------ | --------------------------- |
| Каталог кредитов               | `/#/catalog`                |
| Раскрытый подбор над каталогом | `/#/selection`              |
| Результаты подбора             | `/#/results`                |
| Оформление бизнес-кредита      | `/#/application/business`   |
| Мои заявки                     | `/#/applications`           |
| Карточка примера заявки        | `/#/applications/XX-000123` |
| Вход                           | `/#/login`                  |
| Рабочее место специалиста      | `/#/specialist`             |
| Рассмотрение заявки            | `/#/specialist/XX-001234`   |

Подбор раскрывается внутри страницы. В нём есть сведения о бизнесе, выбор цели и поле «Другое», переключатели залога и действующих кредитов, среднемесячный оборот, сфера деятельности и синхронизированные поля и ползунки суммы и срока. Кнопка помощи показывает ориентировочный диапазон суммы. Обязательные поля отмечены звёздочками.

Кнопка «Подробнее» в каталоге открывает описание, диапазоны сумм и сроков, варианты погашения, особенности и требования к заёмщику из предоставленного PDF «альфа хакатон». Заявка открывается только после отдельного нажатия «Оформить заявку»; гость сначала проходит демонстрационный вход. Закрытие окна сохраняет поиск и категорию каталога.

У клиента в шапке оставлены «Кредиты» и «Мои заявки», у специалиста — «Заявки». Логотип ведёт на главную текущего кабинета. Типы регистрации, возраст бизнеса и отрасли в подборе обновлены по уточнению пользователя.

Сумма и срок доступны для изменения прямо в форме заявки, независимо от входа из каталога или подбора. Новая заявка требует согласие и обязательные документы. Каждый документ прикрепляется нажатием на подписанную строку с иконкой; состав задаётся для продукта и учитывает условные документы из таблицы. При редактировании доступны «Сохранить изменения» и «Отмена», номер и дата исходной заявки сохраняются.

Результат подбора разделён на подходящие продукты, доступные альтернативы и недоступные продукты. Выбор доступного продукта открывает отдельную страницу оформления. После оформления доступны подтверждение, список заявок и карточка со статусом, этапами, документами и показателями.

Кабинеты клиента и специалиста переключаются через меню профиля. В рабочем месте специалиста доступны поиск, фильтр, состояния скоринга, подтверждение решения и предложение других условий. Сохранённые условия видны клиенту: их можно сравнить с исходной заявкой, принять или отклонить.

В списке «Заявки на рассмотрение» остаются заявки без итогового решения и заявки со статусом «Запрошены данные». После одобрения, отказа или предложения других условий заявка уходит из очереди; её данные и статус сохраняются в кабинете клиента и в карточке рассмотрения по прямой ссылке.

В запросе данных специалист выбирает несколько документов: паспорт, годовую финансовую отчётность, действующие кредиты и «Другое» с обязательным описанием. Клиент видит список в заявке и прикрепляет запрошенные файлы. После сохранения заявка возвращается на рассмотрение. Во вкладках «Финансы» и «Проверки» представлены сведения о компании; для новых заявок неизвестные сведения показываются как «Нет данных» или «Не проверено».

## Демонстрационные данные

Бэкенд не используется. Заявки и решения сохраняются в localStorage текущего браузера. Имена прикреплённых документов сохраняются для демонстрации; содержимое файлов не отправляется и не сохраняется после перезагрузки.

Параметры подбора, выбранный продукт и незавершённая форма сохраняются в sessionStorage текущей вкладки. После обновления страницы их можно продолжить заполнять. Согласие на обработку данных нужно подтвердить заново. Повреждённые записи хранилища отбрасываются; при недоступном хранилище интерфейс продолжает работать в памяти.

По умолчанию открыт демонстрационный кабинет клиента. После выхода можно просмотреть макет без авторизации и формы входа:

- Логин клиента: `ivanov123`, пароль для демонстрации: `demo2026`.
- Логин специалиста: `specialist`, пароль для демонстрации: `demo2026`.
- Демонстрационный SMS-код: `4267`; SMS не отправляется.

Ставки и исходное предложение перенесены из макета. Для изменённых параметров используется локальный предварительный расчёт. Скоринг и доступность продуктов иллюстрируют поведение интерфейса, а не выполняют банковскую оценку. Госуслуги, регистрация, восстановление пароля, подписание и выдача кредита требуют будущих интеграций.

## Проверка и сборка

```powershell
npm.cmd exec -- playwright install firefox webkit
npm.cmd run build
npm.cmd run test:e2e
npm.cmd run preview
```

Проверки запускаются в установленном Microsoft Edge и в Firefox и WebKit, установленных Playwright. Для одного браузера: `npm.cmd run test:e2e -- --project=edge`. HTML-отчёт открывается командой `npm.cmd exec -- playwright show-report`.

Полный прогон на готовой сборке:

```powershell
npm.cmd run build
$env:PLAYWRIGHT_PREVIEW='1'
npm.cmd run test:e2e
Remove-Item Env:PLAYWRIGHT_PREVIEW
npm.cmd audit
```

В этом режиме Playwright использует `vite preview` на порту 4173; в обычном режиме — сервер разработки на 5173.

Набор содержит 50 сценариев для каждого браузера: размеры каталога и SVG, условия из PDF, подбор и ручной ввод, комплекты документов, запрос дополнительных данных, сохранение формы, ограничения продуктов, редактирование заявки с отменой, очередь и решения специалиста, сведения о компании, альтернативные условия, вход, ошибочные адреса, повреждённое хранилище, клавиатура, сенсорный ввод и отсутствие ошибок JavaScript и загрузки ресурсов. Адаптивность проверяется на ширинах 320, 375, 768, 1024 и 1366 px, дополнительно на 836 × 508 и 900 × 375. Скриншоты сохраняются в `tests/desktop.png` и `tests/mobile.png`.

axe-core проверяет основные экраны и состояния ошибок, списков и модального окна. Недостаточный контраст исходной палитры Figma фиксируется отдельным вложением `design-color-contrast`; полный WCAG AA не заявляется. Результаты и исправления описаны в [AUDIT.md](AUDIT.md).

Готовая статическая сборка находится в `dist/`.

## Структура

- `src/App.tsx` — навигация и состояние приложения.
- `src/Catalog.tsx`, `src/SelectionPanel.tsx` — каталог, подбор и результаты.
- `src/Applications.tsx` — оформление, список, карточка и условия заявки.
- `src/Login.tsx`, `src/Specialist.tsx` — вход и кабинет специалиста.
- `src/ui.tsx`, `src/styles.css` — общие элементы и стили.
- `src/products.ts`, `src/types.ts` — данные продуктов и демонстрационные данные.
- `src/creditData.ts` — расширенные условия и комплекты документов из PDF; [описание переноса](CREDIT_DATA.md).
- `src/DocumentUploads.tsx` — подписанные поля загрузки и проверка файлов.
- `src/session.ts` — сохранение и восстановление состояния вкладки.
- `public/assets/` — оригинальные локальные ресурсы Figma.
- `FIGMA.md` — соответствие экранов исходному макету.
